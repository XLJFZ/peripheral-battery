# 雷蛇电量核对与稳定性修复

日期：2026-10-30。

截图中 Synapse 显示 91%，托盘显示 94%。截图没有提供两个程序的采样时间，因此不能据此判断哪个值对应同一时刻的硬件状态。

## GitHub 项目对照

| 项目 | 查询与换算 | 对本项目的意义 |
| --- | --- | --- |
| [viper-tray](https://github.com/damianyoko/viper-tray/blob/main/rust/src/battery.rs) | 毒蝰 V3 Pro 使用事务号 `0x1F`、命令 `0x07/0x80`，读取带 Report ID 回包的第 10 字节，按 `raw × 100 / 255` 向下取整 | 与本项目查询方向一致，但设备 PID 不同，不能直接替代炼狱蝰蛇的设备表 |
| [razer-battery-report](https://github.com/xzeldon/razer-battery-report/blob/master/crates/razer-hid/src/device.rs) | 读取 `arguments[1]`，将 0–255 四舍五入为 0–100% | 本项目原有换算与其一致；不是百分比数值被错误地再次缩放 |
| [razer-battery](https://github.com/andrzej-zuralovic/razer-battery/blob/main/src/protocol.rs) | 同样使用 `0x07/0x80`，原始电量在去掉 Report ID 后的第 9 字节，按 255 缩放后向下取整 | 字节偏移差异来自是否包含 Report ID，本项目已分别验证两种格式 |

对同一个原始值，向下取整与四舍五入最多相差 1 个百分点，无法单独解释 91% 与 94% 的差异。上述项目没有为本机提供已验证的 Synapse 校准曲线；不能据此认定 Synapse 使用了某种特定曲线。

## 本机证据

在本机权限下对炼狱蝰蛇 V3 Pro 无线接收器连续做了三次现有只读查询，间隔约 5 秒，均得到 `raw=230`、`90%`、`charging=false`。之后打包的 v0.2.3 诊断程序和本地网页也读到 `230/255 → 90%`。没有向鼠标发送改键、DPI、灯效或固件命令。

本机原始诊断文件保存在工作区的 `docs/evidence/`，未上传包含设备标识的完整记录。这里仅保留型号、原始值和换算结论。

这些读数晚于截图，不能证明截图差距由刷新延迟造成。仍需同一时刻的 Synapse 数字与原始 HID 值才能继续定位。可能的刷新时差、驱动或设备缓存、官方处理差异目前都属于待验证解释。

## 已确认并修正的问题

- HID 后端启动失败、返回失败或解析异常时，现在明确让上一批设备读数失效。
- 同一个 HID 设备本次没有电量时，合并逻辑不再保留旧百分比。
- 托盘电量数字的悬停提示增加原始值和采样时间。
- 网页显示真实报告时间；手动刷新向新版连接器请求重新采样，绕过原有 10 秒缓存。
- 网页读取失败、断连或超过 90 秒未更新时清除百分比，未知电量不再表现为 0%。可导出不含连接令牌的读取记录。
- AirPods / Beats Beacon 与 Fast Pair 附近广播发现继续关闭；QK75N 和 Redmi 音箱 USB 适配继续暂停。

本次保留原有线性换算，没有加入固定修正值。
