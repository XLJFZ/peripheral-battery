# v0.3.4 · 修复面板底部空白与托盘提示精简

## 问题

只有 1～2 台设备时，飞行面板底部会留出一整张设备卡高度的空白（实测窗口 320 DIP，内容只需 217 DIP），页脚被顶到很远的地方。

## 根因

两个原因叠加：

1. **WPF-UI 的 `FluentWindow` 默认 `MinHeight=320`**。面板内容高度只有 217 时，窗口高度被这个下限锁在 320，多出来的 103 全部被设备列表所在的 `*` 行吃掉——`ScrollViewer` 实际高度 205 而内容只需 103，观察到的空白正好是差额。
2. **`SizeToContent="Height"` 不跟随内容收缩**。窗口第一次测量后会把高度写死；空状态（282）切换成有设备（217）时窗口不会变矮。

## 修法

- `MinHeight="0"`，解除窗口高度下限。
- 飞行面板改为 `SizeToContent="Manual"`，由 `FitToContent()` 显式计算：以无限高度测量内容 → 取 `DesiredSize` → `Height = min(desired, MaxHeight)`。设备集合变化（`ItemsControl.Items` 的 `CollectionChanged`）、窗口 `Loaded`、每次 `ShowFlyout` 都会触发一次，差量小于 0.5 像素时不重复设置，避免闪烁。
- 去掉 `ScrollViewer` 的 `MaxHeight="500"`，列表高度统一由窗口 `MaxHeight=660` 约束，长列表滚动时也不会在底部留一段空白。

实测高度（DIP）：

| 场景 | 修复前 | 修复后 | 内容所需 |
| --- | --- | --- | --- |
| 1 台设备（启动即存在） | 320 | 218 | 217.3 |
| 空状态 → 1 台设备 | 320 | 218 | 217.3 |
| 空状态 → 2 台设备 | 320 | 304 | 304 |
| 10 台设备 | 320 / 溢出 | 660（封顶，列表滚动） | 660 |

## 托盘提示精简

托盘提示原来三行、信息冗长：

```
Peripheral · 外设电量
环 1（由外向内）  Razer DeathAdder V3 Pro (Wireless): 76%
```

现在标题只保留"外设电量"，环序号改用 ①②③，设备名去掉型号尾部括号（`(Wireless)`、`（无线）`）并在超过 26 字符时截断，冒号省略；超过 3 台设备时合并为一行"＋N 台，点击查看"：

```
外设电量
① Razer DeathAdder V3 Pro 76%
```

三种语言的标题与"+N 台"文案都补了词条（`Tray_TooltipTitle`、`Tray_MoreDevices`）。

## 新增回归检查

- `--layout-probe <json>`：在空状态、单设备、双设备、十设备四种情形下记录窗口高度、内容期望高度、各行实际高度与滚动区尺寸。
- `tools/check_flyout_layout.py`：运行探针并断言"高度与内容差 ≤ 2 DIP""设备到达后必须收缩""十设备封顶 660 且可滚动"。CI 的 windows 任务和 `build-portable.ps1` 都会执行。
